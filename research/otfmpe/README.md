# OT-FMPE comparison against the Bayesian engine

Research code, not part of the web application. It trains an OT-FMPE network (optimal-transport flow-matching posterior estimation) on the engine's own generative model, and compares it with the engine on the same test cases.

## What OT-FMPE learns

The training data come from `gen.truth`, which is `scripts/run_benchmarks_v2.simulate_truth` with an adjustable mass range. `gen.self_test` checks that the two are identical draw for draw.

The generative model includes:
- the coupled target-class rule;
- the population priors;
- the three scaling packages;
- the layered-band scatter.

So OT-FMPE learns the posterior of the current engine's model, and its best possible result is a tie with the engine on that model.

| | Value |
|---|---|
| Inputs (8) | log10 crater diameter, measurement error (dex), mare fraction, spacecraft flag, optional measured speed (3 % error) and elevation (5°) with masks |
| Outputs (4) | log10 mass, log10 speed, elevation/90, log10 impactor density |
| Training range | craters 5 m – 5 km; measurement error 0.01–0.15 dex; asteroidal and spacecraft populations; 12 crater-size bands × 3 scaling packages in equal shares |
| Data | 2.4 M training and 120 k validation draws (seeds 1000+ and 500000+); test truths use seeds 900000+ |
| Network | AdaLN residual velocity field, 4 blocks × 256, 1.41 M parameters; linear-path flow matching; RK4 sampling, 20 steps, 2,000 samples |
| Training | AdamW (lr 1.5e-3, weight decay 1e-5, cosine), batch 2048, up to 120 epochs with early stopping, 2 × Tesla T4 on Kaggle; 3 seeds |

## Results (log10 mass, three training seeds averaged)

| Test set | Engine MAE (dex) | Engine 90 % coverage | OT-FMPE MAE (dex) | OT-FMPE 90 % coverage |
|---|---|---|---|---|
| `nat_D` asteroidal, diameter only (n = 300) | 0.47 | 0.90 | 0.47 | 0.90 |
| `nat_DVA` asteroidal, with speed and angle (144) | 0.44 | 0.90 | 0.44 | 0.90 |
| `art_D` spacecraft population, diameter only (144) | 0.55 | 0.89 | 0.55 | 0.90 |
| `art_DVA` spacecraft population, with speed and angle (144) | 0.46 | 0.89 | 0.46 | 0.89 |
| `sig_hi` measurement error 0.30 dex, outside training (60) | 0.76 | 0.90 | **3.26** | **0.53** |
| `d_small` craters 2–5 m, outside training (60) | 0.44 | 0.92 | 0.45 | 0.91 |
| `d_large` craters 5–10 km, outside training (60) | 0.50 | 0.87 | 0.51 | 0.86 |
| `mf_02` truth with 0.20 dex model scatter, both assume 0.10 (120) | 0.84 | 0.63 | 0.84 | 0.64 |
| `v_err10` speed error 10 % instead of 3 % (60) | 0.32 | 0.97 | 0.32 | 0.97 |
| `sc_art_D` 11 real spacecraft craters, diameter only | 0.34 | 1.00 | 0.34 | 1.00 |
| `sc_art_DVA` 11 real spacecraft craters, with speed and angle | 0.14 | 1.00 | 0.14 | 1.00 |

Inside its training range OT-FMPE ties the engine, which is the best it can do on the engine's own model. It extrapolates in crater size, but fails when the measurement error leaves the training range (0.30 dex against at most 0.15), where the engine stays calibrated. Both are equally miscalibrated when the true model scatter is larger than assumed (`mf_02`).

The numbers were recomputed independently from the Kaggle posterior samples (`INTERNAL_ONLY/verification/otfmpe_metrics_recompute.py`) and agree with `results/otfmpe_comparison/metrics.json` to 2e-7. The checkpoints reproduce the samples on CPU within Monte Carlo error, and 26 training and validation jobs regenerated by `gen.py` match the Kaggle data files exactly (`INTERNAL_ONLY/verification/`).

Training reached the 120-epoch cap rather than stopping early. Validation loss changed by about 1e-4 (0.08 %) over the last 20 epochs while the cosine schedule took the learning rate to zero, so more epochs would not change these results materially.

## Files

| File | Role |
|---|---|
| `gen.py` | Training and validation data |
| `cases.py` | Shared test cases (in range, stress tests, 11 spacecraft) and the engine's answers on them |
| `train_kaggle.py` | Training (one run per seed) and test sampling |
| `kaggle_run.py` | Upload data, push the Kaggle kernel, wait, fetch outputs. The credential (`kaggle.json`) is read from `KAGGLE_CONFIG_DIR` and never printed |
| `analyze.py` | Metrics: MAE, RMSE, bias, interval coverage, calibration error, interval score, paired differences, variation over seeds |
| `timing.py` | Runtime of both models on the same CPU |

## Reproduce

Run from the repository root. The packages are in the `research` extra (`pip install -e ".[research,test]"`).

1. Training and validation data (2,399,976 and 119,952 rows; deterministic per job seed):

```bash
.venv/bin/python research/otfmpe/gen.py RUN_DIR 2400000
```

2. The 1,114 shared test cases and the engine's answers (`cases.json`, `tests.npz`):

```bash
.venv/bin/python research/otfmpe/cases.py RUN_DIR
```

3. Training on Kaggle (2 x T4). `kaggle_run.py` uploads `train.npz`, `val.npz`, `tests.npz` and `gen_manifest.json` as the private dataset `c2i-otfmpe-v21-data` and pushes `train_kaggle.py` as the kernel `c2i-ot-fmpe-v21`; `wait` and `fetch` follow it and download the checkpoints `fmpe_seed{0,1,2}.pt` and training histories. Training can also run locally on a CPU, slowly: `.venv/bin/python research/otfmpe/train_kaggle.py RUN_DIR RUN_DIR`.

```bash
KAGGLE_CONFIG_DIR=. python research/otfmpe/kaggle_run.py RUN_DIR WORK_DIR dataset
```

```bash
KAGGLE_CONFIG_DIR=. python research/otfmpe/kaggle_run.py RUN_DIR WORK_DIR kernel
```

4. Test sampling. The v21 run uploaded only a 64-case smoke-test `tests.npz` with the training data, so the 1,114 test cases were sampled in a second Kaggle kernel, `c2i-otfmpe-v21-eval-run` (source: `sample_kaggle.py`), from the private dataset `c2i-otfmpe-v21-eval`, which holds `train_kaggle.py` renamed `otfmpe_model.py`, the three checkpoints, and the full `tests.npz` from step 2. This step is not scripted in `kaggle_run.py`; both kernel sources were checked to be identical to the files here. Locally, `train_kaggle.sample_tests(RUN_DIR, RUN_DIR, seed)` does the same.

5. Metrics (`metrics.json`):

```bash
.venv/bin/python research/otfmpe/analyze.py RUN_DIR
```

The results used in the presentation are in `results/otfmpe_comparison/`.
